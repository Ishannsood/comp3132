# Redux + JWT Demo

A small login app that demonstrates **Redux** (state management) and **JWT** (JSON Web Token authentication).
Log in, receive a JWT from the server, keep it in the Redux store, and use it to load a protected page.

- **Frontend:** React + Redux Toolkit + Vite (`/client`)
- **Backend:** Express + `jsonwebtoken` (`/server`)
- **Demo account:** username `demo`, password `password123` (hardcoded, no database)

## How to run

You need Node.js 18 or newer. Open two terminals.

```bash
# Terminal 1: API on http://localhost:4000
cd server
npm install
npm start

# Terminal 2: React app on http://localhost:5173
cd client
npm install
npm run dev
```

Open http://localhost:5173. Install the Redux DevTools browser extension to watch actions and state live.

## How the app works

1. The login form dispatches `login({ username, password })`.
2. The server checks the credentials and returns a signed JWT.
3. The reducer stores the token and user in Redux and sets `isAuthenticated: true`.
4. The Profile page dispatches `fetchProfile()`, which sends the token in an `Authorization: Bearer <token>` header.
5. The server middleware verifies the token and returns protected data.
6. Logout dispatches `logout()`, which resets the state and discards the token.

## Redux concepts and where they appear

| Concept | Meaning | In this app |
|---|---|---|
| **State** | The data the app keeps track of | `{ user, token, profile, isAuthenticated, status, error }` in `client/src/authSlice.js` |
| **Store** | One object that holds all state | `configureStore({ reducer: { auth: authReducer } })` in `client/src/store.js` |
| **Reducer** | A pure function `(state, action) => newState` | The reducers and `extraReducers` inside `createSlice` in `authSlice.js` |
| **Action** | A plain object describing what happened | `auth/login/pending`, `auth/login/fulfilled`, `auth/login/rejected` (generated by `createAsyncThunk`), plus `auth/logout` |
| **Dispatch** | Sends an action to the store | `dispatch(login(...))` and `dispatch(logout())` in `App.jsx` |
| **Subscribe** | Get notified when state changes | `useSelector` in components (subscribes for you), and a raw `store.subscribe(...)` console log in `store.js` |

Redux flow: **component dispatches an action, the reducer returns new state, the store updates, subscribed components re-render.**

## JWT concepts and how it works here

A JWT is a string with three Base64URL parts separated by dots: `header.payload.signature`.

- **Header:** the signing algorithm (here `HS256`) and token type.
- **Payload:** claims such as `sub`, `username`, `role`, and `exp` (expiry). It is encoded, **not encrypted**, so never put secrets in it. The Profile page decodes and displays it.
- **Signature:** a hash of the header and payload made with the server's secret. If anyone edits the payload, the signature no longer matches and the server rejects the token.

In this app, `jwt.sign(...)` creates the token at login (15 minute expiry) and `jwt.verify(...)` in the `requireAuth` middleware checks it on `GET /api/profile`.
Because the server only needs the secret to verify a token, it does not have to store sessions (stateless authentication).

### Where to store the token

| Option | Pros | Cons |
|---|---|---|
| **Memory (Redux state)** (used here) | Not readable by other scripts after a page load; simple | Lost on refresh, so the user logs in again |
| **localStorage** | Survives refresh | Readable by any JavaScript on the page, so an XSS attack can steal it |
| **httpOnly cookie** | JavaScript cannot read it; survives refresh | Needs CSRF protection and server cookie handling |

A production app would usually use a short-lived access token in memory plus an httpOnly refresh-token cookie.

## API

| Method | Route | Auth | Description |
|---|---|---|---|
| POST | `/api/login` | none | Returns `{ token, user }` for valid credentials |
| GET | `/api/profile` | Bearer JWT | Returns protected profile data |
